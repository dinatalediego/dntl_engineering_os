# DNTL Engineering OS

A portfolio control plane for engineering repositories: **discover → inspect → score → observe → prioritize → intervene → refresh**.

## v0.4 — Attention Queue + Repository Side Detail

The product now operates intervention-first instead of repository-first. `data/inventory.json` is generated from observable GitHub evidence and carries three independent control signals:

- **Repository Health**: structural engineering maturity (0–100).
- **Actions Health**: current automation/runtime state from real GitHub Actions executions.
- **Priority Score**: explainable intervention urgency (0–100), generated by `scripts/attention-priority.mjs`.

### Control loop

```text
GitHub repositories + Actions
      ↓
scripts/scan-github.mjs
      ↓
Repository Health + Actions Health
      ↓
Priority Score + evidence
      ↓
data/inventory.json
      ↓
Command Center
      ↓
Attention Queue → Side Detail → intervention
```

`.github/workflows/refresh-inventory.yml` runs every day at **08:17 America/Lima** (13:17 UTC), supports `workflow_dispatch`, runs on relevant pushes to `main`, and now validates relevant pull requests before merge.

Validation gate:

1. `npm run test:health`
2. `npm run scan:github`
3. `npm run build`
4. refreshed inventory commit only outside pull requests

## Repository Health v1

| Dimension | Weight | Observable evidence |
|---|---:|---|
| Freshness | 25 | age of last repository push |
| Documentation | 15 | root README |
| Automation | 20 | GitHub Actions workflow definitions |
| Testing | 20 | test directories/config/files anywhere in the tree |
| Operability | 10 | runtime manifest, Docker or Vercel/Next config |
| Hygiene | 10 | non-archived, non-empty, no tracked `.env`-like files |

Thresholds: **80–100 healthy**, **60–79 watch**, **0–59 risk**, and **Not scanned** only when repository evidence is unavailable.

## Actions Health v1

For repositories with workflows the scanner reads the **10 most recent GitHub Actions runs** and records latest workflow, status/conclusion, branch, trigger, timestamp, duration, recent pass rate, failure count and direct run URL.

Semantics:

- **green**: latest run succeeded
- **red**: latest run failed/timed out/requires action/startup failed/stale
- **yellow/running**: active, cancelled, neutral or skipped
- **idle**: workflow configured with no execution history
- **unknown**: workflow exists but runtime telemetry cannot be read
- **not-configured**: no workflow definition detected

Actions Health remains separate from Repository Health.

## Priority Score v1

The Attention Queue is not manually ordered in React. `scripts/attention-priority.mjs` converts observable signals into deterministic urgency. Runtime failure has the strongest weight; repository risk, missing observability, testing debt, repeated CI failures and tracked `.env` evidence add urgency.

Severity bands:

- **Critical** ≥ 75
- **High** ≥ 50
- **Medium** ≥ 25
- **Low** > 0
- **Clear** = 0

Every contribution is stored as a signal with points, reason and code so the ranking stays explainable.

## Command Center UX

### Attention Queue

The primary screen answers **“what should I intervene on next?”**. It shows rank, Priority Score, severity, primary reason, runtime state and Repository Health. Filters cover priority, Actions state, Repository Health, system type, visibility and text search.

### Repository Side Detail

Selecting a queue item opens a drawer without leaving the operating context. The drawer exposes:

- Repository Health + Actions Health + Priority
- all priority reasons and point contributions
- latest workflow execution and GitHub deep link
- branch, trigger, duration, recent failures and pass rate
- repository evidence (README, tests, workflow definitions, runtime manifest, Vercel signal, tracked `.env`, tree coverage)
- Repository Health components
- direct links to repository and latest run

`Escape` or the backdrop closes the drawer.

## Product architecture spine

The UI now explicitly reserves the operating sequence:

```text
Command Center
    ↓
Attention Queue
    ↓
Side Detail
    ↓
Execution Timeline
    ↓
Dependency Graph
    ↓
Governance Matrix
    ↓
Command Palette
```

The first two intervention surfaces are implemented. The following layers will reuse the Side Detail as the navigation anchor instead of becoming disconnected dashboards.

## Control-plane credential

The repository secret is `DNTL_GITHUB_TOKEN`. For full portfolio + Actions telemetry, use read-only repository access with **Contents**, **Actions** and baseline **Metadata** permissions. Never commit the token itself.

## Next control layers

1. Execution Timeline — multi-run operating history, jobs and failure drill-down.
2. Dependency Graph — repo/data/service relationships and blast radius.
3. Governance Matrix — controls with direct evidence.
4. Command Palette — query and navigate the control plane by intent.
5. Vercel Health — deploy/build/runtime evidence as an independent layer.
6. Supabase/Data Health — migrations, RLS, schema drift, ETL freshness and rejected rows.

Each layer should stay independently auditable before any composite Engineering Confidence Score is introduced.
